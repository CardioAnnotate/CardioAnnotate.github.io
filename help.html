🏠 1. Overview & Getting Started

CardioAnnotate is a browser-based ECG annotation toolkit that allows you to:

  • Load and visualize ECG signals from WFDB files, CSV, or NPZ bundles
  • Manually annotate R, P, T, U, Q, and S peaks across multiple channels
  • Classify R-peaks by beat type using 19 WFDB annotation standards
  • Automatic peak detection using Find Peaks (with optional height bounds) or Pan-Tompkins algorithms
  • Undo and redo annotation edits and peak operations with Ctrl+Z / Ctrl+Y, up to 50 steps
  • Switch the annotation mode from the keyboard and turn the chart's hover boxes on or off
  • Import WFDB annotation files (.atr and wave-specific annotation files)
  • Apply signal processing (resampling, filtering, inversion) and trim the signal to a time range, with one-step undo
  • Compute Signal Quality Indices (SQI) for the visible segment
  • Compute HRV metrics (time-domain and frequency-domain) for the visible segment
  • Detect, review, and correct RR interval outliers through a suggest → preview → apply workflow with Gaussian Process regression
  • Export annotations in JSON, CSV, WFDB, or NPZ format with enhanced options
  • Export the ECG on calibrated clinical paper at a standard paper speed and gain, for printing or saving as a measurable PDF
  • Export and import full sessions in JSON, MAT, or NPZ format to restore the complete analysis state
  • View real-time ECG statistics and intervals
  • Toggle between dark and light themes

💡 100% Privacy-Preserving

All processing happens in your browser using Pyodide (Python in WebAssembly). No data is uploaded to any server.

Peak Types

R-peaks — QRS complex maxima (with beat classification)
P-peaks — Atrial depolarization
Q-waves — QRS onset (minima)
S-waves — QRS termination (minima)
T-peaks — Ventricular repolarization
U-waves — Late repolarization

📂 2. Loading ECG Data

Option A: Load WFDB Files

  1. Click "Choose Files" in the Load section
  2. Select both .hea (header) and .dat or .mat (signal) files with the same basename
    • Example: 100.hea + 100.dat
  3. The signal loads automatically after the file selection is complete

💡 Where to Find WFDB Files

Download ECG databases from PhysioNet (MIT-BIH, LUDB, INCART, etc.)

Loading Status

A small spinner appears next to the signal file input while a signal is loading. It disappears automatically when loading finishes, whether the file loads successfully or an error is reported.

Option B: Load CSV Files

  1. Click "Load" button in the "Import from CSV" row
  2. Select a CSV file containing ECG data

CSV Requirements:

  • First row must be a header with column names
  • Must include one of:
    • fs or sampling_rate column, OR
    • time_s or time column (sampling rate will be calculated)
  • Signal columns should contain numeric values
  • Example columns: fs, time_s, MLII, V1, V2

Option C: Load NPZ Bundle

  1. Click "Load" button in the "Import bundle (.npz)" row
  2. Select an NPZ file previously exported from CardioAnnotate

💡 NPZ Bundles

NPZ bundles are a convenient format that packages the processed signal data, sampling frequency, channel names, all peak annotations, and the trim offset (if the signal was trimmed) into a single compressed file. Use a full session export when you need to restore the complete workspace, including settings, view window, corrections, and computed results.

Option D: Load Full Session

  1. Click the session import control in the Session section
  2. Select a CardioAnnotate session file in .json, .mat, or .npz format
  3. The file format is detected automatically, and the workspace is restored from the saved session state

Full Session Restore

Session import restores the signal viewer, annotations, RR corrections, processing settings, detector settings, selected channel, zoom window, and saved analysis results. SQI, HRV, and stationarity panels are recomputed after import so that the displayed values reproduce the saved session.

📁 3. File Formats (Input & Output)

3.1 Input File Formats

WFDB Format (.hea + .dat/.mat)

The PhysioNet standard format for physiological signals, consisting of two files:

Header File (.hea) Structure:

record_name n_signals sampling_frequency n_samples
filename format gain baseline units resolution 0 0 channel_name
filename format gain baseline units resolution 0 0 channel_name
...
# Optional comment lines starting with #

Example .hea file:

100 2 360 650000
100.dat 212 200 1024 mV 11 0 0 MLII
100.dat 212 200 1024 mV 11 0 0 V5
# Age: 69  Sex: M

Field descriptions:

FieldDescriptionExample
record_nameBase name of the record100
n_signalsNumber of channels2
sampling_frequencySamples per second (Hz)360
n_samplesTotal samples per channel650000
filenameSignal data file name100.dat
formatStorage format (212=12-bit, 16=16-bit, 80=8-bit offset)212
gainADC units per physical unit200
baselineADC zero value1024
unitsPhysical unitsmV
resolutionADC resolution in bits11
channel_nameSignal/lead nameMLII

Signal File (.dat) Structure:

  • Binary file containing interleaved signal samples
  • Format 212: 12-bit samples, 2 samples packed in 3 bytes (little-endian)
  • Format 16: 16-bit signed integers, 2 bytes per sample (little-endian)
  • Format 80: 8-bit unsigned with offset 128
  • Physical value = (ADC_value − baseline) / gain

Format 212 Byte Layout

Two 12-bit samples (A, B) stored in 3 bytes:

Byte0 = A[7:0], Byte1 = B[3:0]|A[11:8], Byte2 = B[11:4]

CSV Format (.csv)

Comma-separated values with a header row.

Structure:

fs,time_s,MLII,V1,V5
360,0.000000,0.123,-0.045,0.089
360,0.002778,0.125,-0.043,0.091
360,0.005556,0.128,-0.041,0.094
360,0.008333,0.132,-0.038,0.098
...

Required columns (one of the following):

Column Name(s)Description
fs, sampling_rate, or sampling_frequencySampling rate in Hz (same value repeated each row)
time_s or timeTime in seconds (fs calculated from Δtime)

Signal columns:

  • Any numeric column not in the exclude list becomes a channel
  • Excluded column names: fs, sampling_rate, sampling_frequency, time_s, time, index, sample
  • Values should be in physical units (e.g., mV)

NPZ Bundle Format (.npz)

Compressed NumPy archive containing signal data and metadata.

Structure:

{
  "signals": numpy.ndarray,     // Shape: (n_channels, n_samples), dtype: float64
  "meta": JSON string           // Metadata as serialized JSON
}

Meta JSON structure:

{
  "fs": 360,                              // Sampling frequency in Hz
  "channelNames": ["MLII", "V1", "V5"],   // Array of channel names
  "units": ["mV", "mV", "mV"],            // Units per channel (optional)
  "recordBase": "100",                    // Original record name (optional)
  "trimOffsetSec": 0,                     // Start offset (s) from the loaded record if trimmed (optional, v0.4.0+)
  "annotations": {                        // Peak annotations
    "R": {
      "0": [                              // Channel index as string key
        {"index": 77, "type": "N"},       // R-peaks: objects with index and type
        {"index": 370, "type": "N"},
        {"index": 662, "type": "V"}
      ],
      "1": [{"index": 79, "type": "N"}]
    },
    "P": {
      "0": [30, 320, 610],                // Other peaks: arrays of sample indices
      "1": [32, 322]
    },
    "Q": {"0": [70, 363, 655]},
    "S": {"0": [85, 378, 670]},
    "T": {"0": [180, 475, 765]},
    "U": {"0": []}
  }
}

Legacy bundles that use peaks for the annotation map may still be loaded when supported by the importer.

3.3 Full Session Format

A full session file stores the complete state of an analysis in a single, self-contained container. Use this format when an analysis must be paused and resumed, archived, shared with collaborators, or reopened exactly as it was left.

Recorded Session State

State CategoryWhat Is Stored
Signal dataThe current processed waveform for every channel and the original unmodified signal, together with sampling frequency, channel names, physical units, and record identifier. Retaining both processed and original signals keeps filtering, resampling, inversion, and reset available after reload. If the signal was trimmed, both are stored already trimmed, together with the cumulative trim offset (seconds from the start of the loaded record).
Annotations and correctionsAll fiducial annotations, R-peak beat-type labels, and the full RR review state — every flagged case, its structural suggestion and confidence, the selected/applied action, GP correction metadata, and the undo history. The annotation undo/redo history and the Undo trim snapshot are working-session aids and are not saved.
Processing and analysis settingsFiltering and resampling parameters, per-peak-type detector settings for Find Peaks (including height bounds) and Pan-Tompkins, trim range inputs, RR quality-control rules, selected GP kernel and hyperparameters, SQI parameters, and interface-control state including the two hover-box checkboxes.
View and selectionThe active channel and current zoom window. Because SQI and HRV are evaluated on the visible segment, saving the window fixes the exact sample range used for segment-level analysis.
Computed resultsA provenance snapshot of reported measures, including pSQI, kSQI, basSQI, lineSQI; time- and frequency-domain HRV metrics; the ADF stationarity test; and summary statistics.

✏️ 4. Peak Annotation

Basic Annotation Workflow

  1. Select a Channel from the dropdown
  2. Use the mouse scroll wheel or plot controls to zoom into a region of interest
  3. Select an annotation Mode, with the pointer or with the number key shown beside each option (see 4.2 Keyboard Shortcuts):
    • Navigate 0 — Pan and zoom only
    • Add R (Normal) 1 — Click to add R-peaks (default type: Normal)
    • Add P 2 — Click to add P-peaks
    • Add T 3 — Click to add T-peaks
    • Add U 4 — Click to add U-waves
    • Add Q 5 — Click to add Q-waves
    • Add S 6 — Click to add S-waves
    • Remove nearest 7 — Click near a peak to delete it
  4. Click on the signal where you want to place peaks

💡 Zoom Persists

Your zoom state is preserved when switching channels or annotation modes. The plot remembers where you were working.

Snap to Peak

After placing peaks approximately, you can refine them automatically:

  1. Enter a window size (e.g., 4-10 samples) in the "Snap peaks" field
  2. Click "🎯 Adjust"
  3. All R, P, T, and U peaks will snap to the local maximum within the window

Snapping can be reverted with "↶ Undo (Ctrl+Z)" (see below).

⚠️ Q and S Waves Are Not Snapped

Q and S waves are typically minima or inflection points, so they are excluded from the snap function. These must be placed precisely by hand.

Undo Annotations

↶ Undo (Ctrl+Z) / ↷ Redo (Ctrl+Y)

The "↶ Undo (Ctrl+Z)" and "↷ Redo (Ctrl+Y)" buttons (next to "Clear peaks") step backward and forward through every change to the annotations, one at a time. Ctrl+Z and Ctrl+Y do the same thing from the keyboard (Cmd on macOS; Ctrl+Shift+Z also redoes), so a misplaced click can be taken back without leaving the plot.

Both the manual edits and the bulk operations are recorded:

Recorded changeWhere it comes from
Add a peakA click on the signal in any "Add" mode
Remove nearestA click on the signal in "Remove nearest" mode
Remove last annotationThe "↶ Remove Last" button
Classify an R-peakA quick classify button, a keyboard beat label, the "More..." panel, or right-click classification
Detect & assignAutomatic detection (Section 4.3)
Snap/AdjustSnap peaks to local maximum
Clear peaksThe "Clear peaks" button

Up to the last 50 changes can be undone. Hover over either button to see which change it will undo or redo, and how many steps are available. Undo restores all annotations on every channel, the "Remove Last" history, and the RR review state to exactly how they were just before that change; redo puts back exactly what was undone.

  • Edits made after a change are reverted along with it when you undo that change.
  • Any new change clears the redo history.
  • If you edit annotations after an undo, Redo asks for confirmation before discarding those edits.
  • RR corrections applied after an undone change are reverted with it and come back on redo.
  • Actions that change nothing are not recorded: a snap that moves no peak, clearing when no peaks exist, a "Remove nearest" click with no peak in range, or re-applying the beat label a peak already has.

↶ Remove Last

Click "↶ Remove Last" to remove the most recent peak annotation. This button works through the annotations in the reverse order they were added, which is useful for walking back a run of peaks you placed. It is itself undoable with Ctrl+Z.

The difference from Undo: Remove Last always deletes a peak, even if your most recent action was something else (a classification, a detection run). Undo reverses whatever the last change actually was.

⚠️ When the Undo/Redo History Is Cleared

Because the history refers to sample positions, it is cleared when you load a new record, session, or annotation file, trim the signal, undo a trim, or reproject annotations after resampling. The history is not saved in session files.

Undo Depth on Very Long Records

Each recorded change stores a complete copy of the annotations, so the history is limited by an approximate memory budget as well as by the 50-step count. On an ordinary record the full 50 steps are available; on a very long recording holding tens of thousands of peaks, the oldest steps are dropped earlier and the usable depth is smaller. Undo and redo always keep at least the most recent step.

Clear All Peaks

Click "Clear peaks" to remove all R, P, Q, S, T, and U annotations. A confirmation dialog will appear. Clearing can be reverted with "↶ Undo (Ctrl+Z)".

Invert ECG

Click "Invert ECG" to multiply all signal values by -1. Useful for signals with inverted polarity.

4.1 R-Peak Beat Classification

CardioAnnotate supports comprehensive beat-by-beat R-peak classification following WFDB annotation standards. Each R-peak can be classified into one of 19 different beat types for arrhythmia analysis.

How to Classify R-Peaks

Method 1: Quick Classify Buttons

After adding an R-peak, use the quick classify buttons for common types:

  • N — Normal beat
  • V — Premature ventricular contraction (PVC)
  • A — Atrial premature contraction (APC)
  • L — Left bundle branch block (LBBB)
  • R — Right bundle branch block (RBBB)

Simply add an R-peak, then click the appropriate quick classify button.

Method 2: Full Classification Panel

Click "More..." to access the complete classification panel with all 19 beat types. The panel shows:

  • Current beat type and sample position
  • Full list of WFDB annotation codes
  • Beat type descriptions

Method 3: Right-Click Classification

Right-click near any R-peak on the plot to open the classification panel for that specific peak. This is the fastest way to classify previously-added R-peaks.

When the Shortcuts Are Live

Shortcuts act on the chart, so they step aside whenever a key belongs to the control you are using:

  • All of them are ignored while the cursor is in a text or number field or a text area, so typing a cutoff frequency or a record name is never hijacked and the browser's own undo still works there.
  • They stay live while a checkbox, radio button, slider, file picker or button has focus — clicking one of those does not switch the shortcuts off.
  • The mode keys also work while the Mode selector itself has focus, which is where the pointer leaves it after you pick a mode by hand. They are ignored while a different dropdown has focus, because some of those (Notch, Mains, ± width) have options beginning with a digit, where typing one is that dropdown's own shortcut.
  • The beat-label letters are ignored while any dropdown has focus, since letters drive its option type-ahead.
  • Ctrl+Z and Ctrl+Y work from any dropdown, checkbox or button.
  • Apart from the undo and redo combinations, no shortcut fires while Ctrl, Cmd or Alt is held, so browser and system accelerators such as Ctrl+S and Ctrl+A are left alone.

If a shortcut seems unresponsive, the cursor is most likely still in a text or number field: click once on the plot and press the key again.

4.3 Automatic Peak Detection

CardioAnnotate provides two automatic peak detection algorithms that can be used for any peak type:

Find Peaks (scipy.signal.find_peaks)

A general-purpose peak detection algorithm suitable for all peak types. Configurable parameters:

  • Polarity: Detect maxima, minima, or absolute value maxima
  • Min distance (ms): Minimum distance between consecutive peaks
  • Threshold: Simple cutoff on the raw signal value, in signal units: x ≥ threshold for Maxima, x ≤ threshold for Minima, and |x| ≥ |threshold| for |x| maxima (optional)
  • Height: Required peak height, in signal units, following the height argument of SciPy's find_peaks (optional; see below)
  • Prominence: Minimum vertical prominence required
  • Prom window (ms): Window size for prominence calculation

Pan-Tompkins Algorithm

A classic QRS detection algorithm optimized for R-peak detection. Parameters:

  • Band-pass (Hz): Frequency range for filtering (default 5–15 Hz)
  • MWI (ms): Moving window integration width
  • Min RR (ms): Minimum allowed RR interval
  • Thresh k: Threshold factor (detection threshold = mean + k·std)
  • Refine ± (ms): Window for refining detected peaks to local maximum

Find Peaks Height Bounds

The Height field accepts nothing, one number, or two numbers. The first number is always the minimum, and the second, if supplied, is the maximum:

EntryMeaning
(blank) or NoneNo height limit

0.5, 1.20.5 ≤ height ≤ 1.2
None, 1.2 or , 1.2Height ≤ 1.2 (maximum only)

The two numbers may also be separated by a space or semicolon, or written in brackets, e.g. [0.5, 1.2] or (0.5; 1.2). If the minimum is greater than the maximum, a value is not a number, or more than two values are entered, detection does not run and an error is shown in the status badge.

As in SciPy (where minima are found by running find_peaks(-x, height=...)), the height a peak is compared against depends on the polarity:

  • Maxima: the signal value x
  • Minima: the depth −x. For example, 0.2, 1 keeps troughs whose value lies between −1 and −0.2.
  • |x| maxima: the absolute value |x|

The Height value is saved per peak type together with the other detector settings, and in full sessions.

Detection Scope

  • Full signal: Process the entire recording
  • Visible segment: Process only the current zoom window

Options

  • Replace existing (in scope): If checked, removes existing peaks of the target type before detection

Every detection run that assigns peaks can be reverted with "↶ Undo (Ctrl+Z)" and reapplied with "↷ Redo (Ctrl+Y)" (see Undo and Redo).

💡 Save Settings per Peak Type

Click "💾 Save settings to this peak type" to remember your detection parameters for each peak type. The tool will remember different settings for R, P, T, etc.

💡 Detection Tips

  • For R-peaks, Pan-Tompkins usually works best
  • For P and T waves, use Find Peaks with appropriate polarity and distance settings
  • For Q and S waves, use Find Peaks with "Minima" polarity
  • Use a Height range to separate peaks of different sizes, e.g. a minimum height to skip small P or T waves when detecting R-peaks, or a maximum to exclude large artifacts
  • Run detection on a visible segment first to tune parameters before processing full signal

Warnings Before You Print

The form warns before producing a long page set, and when the rows are too short for the chosen gain — for example, a row that can only show ±0.6 mV will clip ordinary R waves at 10 mm/mV. The remedy is fewer rows per page, a larger page, or a lower gain. The warning is stated in millivolts rather than millimeters, because that is what determines whether a deflection fits.

How the Trace Is Drawn

  • Traces use min/max decimation at roughly one printer pixel per bin, so a narrow QRS spike keeps its full height on a long segment instead of being thinned away by point-skipping.
  • A deflection taller than its row is clipped at the row boundary rather than drawn over the neighboring lead.

🔧 6. Signal Processing

Resampling

Change the sampling frequency of your signal:

  1. Enter the target sampling frequency in Hz
  2. Click "Resample"
  3. The signal will be resampled using scipy.signal.resample_poly
  4. If you have annotations, you'll be warned that they need to be reprojected

⚠️ Important: Reproject Annotations After Resampling

After resampling, your peak annotations will be at incorrect positions. Click "Reproject annotations to new fs" to automatically scale them to the new sampling rate.

Filtering

Apply Butterworth filters (order 4, zero-phase using filtfilt):

Low-Pass Filter

Remove high-frequency noise. Enter cutoff frequency in Hz (e.g., 40 Hz).

High-Pass Filter

Remove baseline wander and low-frequency drift. Enter cutoff frequency in Hz (e.g., 0.5 Hz).

Notch Filter

Remove powerline interference at 50 Hz or 60 Hz. Select from dropdown (Q=30).

Band-Pass Filter

Convenience shortcut that applies high-pass and low-pass in one step. Enter low and high cutoff frequencies.

💡 Typical ECG Filter Settings

Common band-pass: 0.5 Hz (high-pass) to 40 Hz (low-pass). This removes baseline drift while preserving ECG morphology.

Trimming

Shorten the recording to a time range. All channels are trimmed together, and annotations move with the signal.

Trim to a Start/End Range

  1. Enter Start and End and choose the units, seconds or samples. Switching units converts values you have already entered.
  2. Optionally click "Use visible window" to fill both fields from the current zoom.
  3. Click "✂ Trim" and confirm.

The kept range is [start, end): the end is exclusive, like a Python slice. For example, 0–10 s at 360 Hz keeps exactly 3600 samples. Leave Start blank to keep from the beginning, or End blank to keep to the end of the signal. An End beyond the signal length is clamped to the end.

✂ Trim to Visible Window

Click "✂ Trim to visible window" to keep exactly the samples currently shown in the plot.

What Happens to Annotations and Other State

  • Annotations inside the kept range shift to the new start (sample indices are renumbered from 0); those outside are dropped. R-peak beat types and peak identifiers are kept.
  • The original (pre-processing) signal is trimmed to the same time span, so "↺ Reset all signals" stays aligned with the shifted annotations. This also holds after resampling, because the span is converted to the original sampling frequency.
  • RR review cases, the RR correction undo history, the "Remove Last" history, and the annotation undo/redo history are cleared, because they refer to the old sample positions.
  • The plot zooms out to show the whole trimmed signal, and the start/end fields are cleared.
  • The cumulative trim offset (seconds from the start of the loaded record) is shown as Trimmed (start offset) in the metadata panel and is stored in NPZ bundles and full sessions. Repeated trims add up.

↶ Undo Trim

Click "↶ Undo trim" to restore the signal, annotations, and RR review state exactly as they were immediately before the last trim. Only the most recent trim can be undone, and any changes made after trimming (annotations, filtering, resampling, RR review) are lost when you undo it. A confirmation dialog appears first.

⚠️ Trimming Is the New Baseline

"↺ Reset all signals" does not undo a trim; it returns to the original signal over the trimmed time span. Use "↶ Undo trim" to recover the removed data, or reload the record. The Undo trim snapshot is cleared when a new record or session is loaded and is not saved in session files.

Reset to Original

Click "↺ Reset all signals" to discard all signal processing (resampling, filtering, inversion) and return to the originally loaded signal. If the signal was trimmed, the original signal is returned over the trimmed time span.

⚠️ Filter Order Matters

If you plan to both resample and filter, resample first, then filter. Filters are designed for specific sampling rates.

Poincaré SD2 (ms) Dispersion along the line of identity (SD2 = √(2·SDNN² − ½·SDSD²)) Long-term variability; reflects overall HRV and satisfies SD1² + SD2² = 2·SDNN²
SD2/SD1 Ratio of long-term to short-term variability Balance between long- and short-term variability; higher values indicate greater long-term dispersion relative to beat-to-beat variability
SampEn Sample entropy of the NN series (embedding dimension m = 2, tolerance r = 0.2 × SDNN) Regularity and complexity of the RR series; lower values indicate more regular, predictable rhythms, higher values indicate more complex or irregular dynamics

Stationarity (ADF Test)

The Augmented Dickey-Fuller test assesses whether the RR interval series is stationary:

  • Stationary (p < 0.05) — RR intervals show stable statistical properties; HRV metrics are reliable
  • Non-stationary — RR intervals show trends or drifts; interpret HRV metrics with caution

⚠️ HRV Requirements

Time-domain HRV requires ≥2 R-peaks (to compute at least one RR interval). Frequency-domain HRV requires ≥4 RR intervals for reliable spectral estimation.
Nonlinear metrics require ≥3 NN intervals for the Poincaré descriptors; SampEn requires at least m+2 intervals and is reported as "—" when no matching templates exist at the chosen tolerance, so it is most reliable on longer segments with many intervals.

7.4 RR Error Detection & Review-Based Correction

CardioAnnotate flags implausible RR intervals and helps you resolve them, but no annotation is ever changed automatically. Every correction moves through four stages — detection, structural suggestion, preview, and apply — and only the final, explicit "Apply" click commits a change to the peak annotations. This review-based workflow replaces the earlier single-click "detect → auto GP-correct → auto delete" pipeline.

Stage 1 — Detection

Click "Detect RR outliers" to flag suspicious RR intervals in the visible segment. Detection only flags intervals and generates suggestions for stage 2 — it never modifies an annotation.

Click "Apply" in the review panel to commit the previewed change to the peak annotations, recompute HRV/SQI, and record the case as reviewed. Workflow

  1. Configure detection parameters (min/max RR, max change α) and, if needed, the structural thresholds
  2. Select a GP kernel and adjust the GP hyperparameters sliders if needed
  3. Click "Detect RR outliers" to flag implausible intervals and generate structural suggestions

  5. Choose an action (GP timing correction, add/delete/move a peak, or retain as physiological) and inspect the preview overlay

A GP-based proposal (timing correction or missing-beat reconstruction) requires at least 2 accepted (non-flagged) RR intervals in the segment to train the model. If a proposal fails, try adjusting the detection or structural thresholds so fewer intervals are excluded from training, or try a different kernel (RQ is usually most robust).

💡 When to Review RR Corrections

Detect and review flagged RR intervals before computing HRV metrics, and apply (or explicitly retain) each case. This removes or corrects ectopic beats, missed beats, and artifacts that would otherwise distort HRV estimates — and because each decision is explicit, the audit table and exported metadata document exactly why every correction was made.

💡 9. Tips & Best Practices

1. Work at the Right Zoom Level

Zoom in to 2-3 heartbeats for optimal annotation precision. You can see the overall morphology while placing peaks accurately.

2. Annotate R-peaks First, Then Classify

The most efficient workflow is to add all R-peaks first with the default "Normal" type, then use keyboard shortcuts or quick classify buttons to mark arrhythmias as you go. For complex cases, right-click on R-peaks to access the full classification panel.

3. Use Snap-to-Peak for Refinement

Place approximate peaks quickly, then use the snap function with a small window (3-5 samples) to refine them automatically. This works best for R, P, T, and U peaks.

4. Save Your Work Frequently

Export annotations to JSON or a signal bundle to preserve peak labels. Use full session export when you need to preserve the complete workspace, including the original and processed signals, settings, corrections, selected window, and computed results. Since everything runs in-browser, refreshing the page will lose all unsaved work.

5. Process Then Annotate

Apply necessary filtering and resampling before annotating. It's easier to see features in clean, properly-sampled signals.

6. Multi-Lead Consistency

For multi-lead ECGs, annotate the clearest lead first (often MLII), then use those annotations as a temporal reference for other leads.

7. Q and S Wave Annotation

Q and S waves require precise manual placement since they're often minima or inflection points. They are automatically excluded from the "snap to peak" function. For accurate QRS measurements, annotate both Q and S waves.

8. Use Ctrl+Z for Quick Corrections

If a click lands in the wrong place while annotating, press Ctrl+Z and click again — far faster than switching to "Remove nearest" mode and back. The same key reverses a mistaken classification, a whole detection run, a snap, or a "Clear peaks". Use "↶ Remove Last" when you specifically want to delete the most recently added peak rather than reverse your last action, whatever it was.

9. Choose the Right WFDB Export Mode

For general-purpose exports and maximum compatibility, use the single file mode. Use separate files mode when you need to process different peak types independently or when working with specialized WFDB tools.

10. Review Flagged RR Before HRV Analysis

Before computing HRV metrics, run RR outlier detection and step through the review panel for each flagged case — applying a correction or explicitly retaining it as physiological. This removes or corrects ectopic beats and artifacts that would otherwise distort HRV estimates, while keeping a record of every decision.

11. Check Signal Quality First

Review the SQI metrics before detailed annotation. Poor signal quality (low pSQI, high lineSQI) may require filtering or indicate a segment unsuitable for analysis.

12. Trim Before Detailed Analysis

If only part of a recording is usable (for example, the first minutes are noisy or the electrodes came off at the end), trim it before running detection and RR review. Trimming after a long review clears the RR review history, so it is best done early.

13. Tune Detection with Undo

Try a detection setting on the full signal, and if the result is not right, press Ctrl+Z (or click "↶ Undo (Ctrl+Z)"), adjust the Height, distance, or threshold, and run again. Use Ctrl+Y to flip back and forth and compare against the previous result.

14. Keep One Hand on the Number Keys

When a record needs more than one peak type, press the mode number instead of returning to the Mode selector between peaks — 1 for R, 2 for P, 3 for T, 7 to remove the nearest peak. Combined with Ctrl+Z and the beat-label keys, a full pass over a segment needs no pointer travel outside the plot.

16. Check the Calibration Before Measuring a Printout

When an exported ECG will actually be measured, confirm the print came out to scale before reaching for the calipers: a large square should measure exactly 5 mm with a ruler, and the calibration pulse should stand exactly as tall as the gain printed in the footer (10 mm at 10 mm/mV). If either is short, the print dialog scaled the page — set Scale to 100% and Margins to None and print again.

15. Use Full Sessions for Reproducibility

When sharing an analysis with collaborators or preparing work for review, export a full session rather than only annotations. The session records the visible segment, detector parameters, GP correction state, and computed SQI, HRV, and ADF results needed to reproduce the workspace.

🔧 10. Troubleshooting

Common Issues

Issue: "Initializing..." never completes

Solution: Check your internet connection. Pyodide and WFDB need to download (~20MB) on first load. Try refreshing the page or clearing your browser cache.

Issue: "Failed to load" WFDB files

Solution: Ensure you have both .hea and .dat (or .mat) files with the same basename. Check that the files aren't corrupted. Try the files with standard WFDB tools first.

Issue: Annotations disappear after resampling

Solution: This is expected behavior. Use the "Reproject annotations to new fs" button to scale peak positions to the new sampling rate.

Issue: CSV import fails

Solution: Verify your CSV has:

  • A header row with fs or sampling_rate column
  • Channel columns with recognizable names
  • Numeric values in all data rows
  • No missing values

Issue: Filter causes error

Solution: Make sure cutoff frequencies are below the Nyquist frequency (sampling_rate / 2). Very low or very high cutoffs can cause numerical issues.

Issue: Peaks not visible on plot

Solution: Zoom out to see the full signal range. Annotations are only visible when the corresponding samples are in the current view window.

Issue: Beat classification not working

Solution: Beat classification only works for R-peaks. Make sure you're in "Add R (Normal)" mode or have recently added an R-peak. The beat-label keys only classify the most recently added R-peak.

Issue: A keyboard shortcut does nothing

Solution: The cursor is most likely still in a text or number field — a filter cutoff, a snap window, a record name — where every shortcut deliberately stands aside so typing works normally. Click once on the plot and press the key again. Two more cases to check:

  • A number key with a dropdown other than Mode focused. Notch, Mains and ± width have options beginning with a digit, so digits belong to those dropdowns. Click the plot first.
  • A beat-label letter with any dropdown focused. Letters drive a dropdown's own option type-ahead. Click the plot first.

Holding Ctrl, Cmd or Alt also suppresses every shortcut except undo and redo, so that browser and system accelerators keep working. The 8 and 9 keys are not assigned to anything. See When the Shortcuts Are Live for the full rules.

Issue: A hover box covers the peak I am trying to click

Solution: Clear the Annotation tooltips checkbox in the viewer controls row, and the Hover coordinates checkbox as well if the trace readout is also in the way. Clicking to add, remove, classify, or open an RR review case keeps working with the boxes hidden (Section 4.4).

Issue: WFDB annotation file is not visible in the file picker

Solution: The WFDB annotation importer accepts all file extensions. Choose the file directly, or switch the operating system file picker to show all files, then select the desired .atr, .qrs, .pwave, .twave, .uwave, .qwave, or .swave annotation file.

Issue: WFDB export creates unexpected files

Solution: Check your selected export mode (single file vs. separate files). The "single file" mode creates one .atr file, while "separate files" mode creates multiple annotation files (.atr, .pwave, .twave, etc.) depending on which peak types you've annotated.

Issue: A GP-based proposal (timing correction / add missing peak) fails or returns poor results

Solution: These proposals require at least 2 accepted (non-flagged) RR intervals in the segment to train the model. Try adjusting the detection or structural thresholds so fewer intervals are excluded from training, or try a different kernel (RQ is usually most robust). If the reconstructed intervals fall outside the absolute RR bounds, the proposal is rejected — widen the bounds or choose a different action (e.g. "Retain as physiological") for that case.

Issue: Detection shows a "Height" error and nothing is detected

Solution: The Height field accepts at most two numbers, and the first must not be greater than the second. Enter nothing, a single minimum (e.g. 0.5), or min, max (e.g. 0.5, 1.2). For Minima polarity, enter positive depths (e.g. 0.2, 1 for troughs between −1 and −0.2).

Issue: Some annotations are missing after trimming

Solution: Annotations outside the kept range are removed. Remember the end is exclusive. Click "↶ Undo trim" to restore them, then trim again with a wider range.

Issue: The Undo/Redo buttons are grayed out

Solution: There is nothing to undo or redo. The history is cleared when you load a record, session, or annotation file, trim, undo a trim, or reproject annotations, so it starts empty after any of those. Redo is also cleared by any new change. Note that actions which changed nothing are never recorded — a snap that moved no peak, a "Remove nearest" click with no peak in range, or re-applying a beat label a peak already had.

Issue: HRV metrics show "—"

Solution: HRV requires R-peaks in the visible segment. Time-domain metrics need ≥2 R-peaks; frequency-domain metrics need ≥4 RR intervals. Zoom to include more heartbeats.

Issue: NPZ import fails

Solution: Ensure the NPZ file was exported from CardioAnnotate and contains both "signals" and "meta" arrays. Files from other sources may not be compatible.

Issue: Full session import does not restore the expected workspace

Solution: Confirm that the file is a CardioAnnotate full session rather than an annotation-only JSON/CSV file or a signal bundle. Full sessions include signals, annotations, corrections, settings, view state, and results. If the visible segment differs after import, check that the saved session contained the expected zoom window and active channel.

Issue: The printed ECG does not measure correctly

Solution: The print dialog almost certainly scaled the page. Set Scale to 100% rather than "Fit to page", set Margins to None, and select the same paper size you chose in the export form. Verify with a ruler: one large square must be 5 mm, and the calibration pulse must match the gain printed in the footer.

Issue: The 12-lead layouts are not offered

Solution: The 3 × 4 and 6 × 2 layouts appear only when all twelve standard leads are recognized in the channel names. Check the channel list in the metadata panel: a record missing a lead, or using names the importer cannot match to a standard lead, falls back to the stacked and continuous-strip layouts, which work with any channel count. Common spellings including MLII, AVR, and v5 are recognized; see Clinical ECG Export.

Issue: Tall QRS complexes are cut off in the exported ECG

Solution: The rows are too short for the chosen gain, and the form warns about this before generating, stating how many millivolts a row can show. Reduce the rows per page, use a larger page or landscape orientation, or lower the gain from 10 to 5 mm/mV. Note that changing the gain changes the vertical scale of the printout, so the footer value must be read when measuring amplitudes.

Issue: The ECG export or report window does not open

Solution: Both open a new window, so a pop-up blocker will stop them. Allow pop-ups for this page in the browser's address bar, then click the button again.

Performance Tips

  • Large Files: For signals >1 million samples, operations may take several seconds. Be patient and watch the console log for progress.
  • Browser Choice: Chrome/Edge typically perform best. Firefox and Safari also work but may be slower for very large signals.
  • Memory: Very large multi-channel recordings may exceed browser memory limits (typically ~2GB). Consider downsampling or processing channels separately.
